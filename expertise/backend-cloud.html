Backend & Cloud

Geospatial products people can use — APIs, alerts and dashboards in production.
  • Home
  • What I do
  • Backend & Cloud

Overview

Analysis only matters when it reaches the person who has to act. I build the Django, FastAPI and PostGIS backends, real-time feeds and alerting that turn EO and sensor data into working services, and I deploy them reproducibly.

What you get

  • Spatial REST and WebSocket APIs on Django or FastAPI with PostgreSQL / PostGIS
  • IoT ingestion over MQTT and scheduled satellite processing with Celery
  • Alerting through WhatsApp and SMS, PDF reporting and live dashboards
  • QGIS plugins that bring your service into analysts' existing tools
  • Dockerised deployments on AWS, with automated tests and CI

Who this helps

  • Early-warning programmes

    Flood, hazard or crop alerts that must reach communities quickly.

  • Energy & infrastructure developers

    Fast, explainable screening of candidate sites.

  • Start-ups & product teams

    Location-aware products that need a solid spatial backend and API.

  • Research teams

    Turning a working notebook into a service others can use.

How I approach it

  1. 01

    Model the domain spatially first

    Design the PostGIS schema around the real-world entities, such as gauges, catchments, sites and constraint layers, so every output traces back to its data.

  2. 02

    Design for the latency the decision needs

    Site screening was designed for sub-500 ms assessments, using Redis and spatially indexed layers; batch jobs run on Celery schedules.

  3. 03

    Ingest real-world data robustly

    MQTT from ESP32 sensors, scheduled Sentinel-1 / 2 processing and validated inputs, so the service keeps running when one feed fails.

  4. 04

    Deliver where users already are

    WhatsApp and SMS alerts, QGIS plugins, PDF reports and live WebSocket dashboards rather than another login.

  5. 05

    Ship in phases, with tests

    Flood Watch shipped in five delivery phases, each with its own automated tests, so new features do not break earlier ones.

  6. 06

    Deploy reproducibly

    Docker and AWS (EC2, S3), with GitHub Actions CI and split settings for each environment.

Common questions

Do you build the front end too?

I focus on backends, APIs and data, and build dashboards and server-rendered interfaces (for example Django with HTMX). For complex single-page front ends I can pair with a front-end specialist.

Where will it be hosted?

Wherever suits you: AWS or your own servers. Everything is containerised with Docker.

Can you integrate with our existing GIS?

Yes. Services expose standard APIs and formats, and a QGIS plugin can bring results directly into analysts' projects.
